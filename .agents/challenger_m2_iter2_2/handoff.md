## 3. Caveats

1. **Interactive OpenGL Grab vs Headless Mode**:
   - Interactive OpenGL viewport grab (`bpy.ops.render.opengl`) requires an active graphical window manager context (`VIEW_3D` area and window). In background headless mode (`blender.exe --background`), `capture_viewport_image` automatically and correctly falls back to the Workbench render engine (`bpy.ops.render.render` with `BLENDER_WORKBENCH`), producing valid image output.
2. **Monolithic Headless Script Template**:
   - In `_generate_headless_script()`, methods share a monolithic template that includes an `execute_custom_script` branch with `exec()` and a bottom exception handler with `import traceback`. These scripts are intended for standalone subprocess execution (`blender.exe --background --python <file>`) where `AddonSecurityValidator` does not run. For socket RPC, `_generate_interactive_script()` is dispatched instead, which fully complies with `AddonSecurityValidator`.
3. **Live Socket Tests Skipped in Headless CI**:
   - 3 live socket probe tests in `test_adversarial_viewport_capture.py` skip cleanly when no interactive Blender instance is listening on port 9876. This is expected behavior documented in the test suite.
